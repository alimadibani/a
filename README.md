# InboxLoops — تعليمات النشر على Vercel

## البنية
```
inboxloops/
├── public/
│   ├── index.html   ← الموقع الرئيسي (تصميم + مساعد ذكي)
│   ├── admin.html   ← لوحة تحكم الوكالة (دخول حقيقي بإيميل/كلمة مرور)
│   ├── review.html  ← صفحة مراجعة العميل (تُفتح من رابط مباشر)
│   └── portal.html  ← أرشيف نشرات العميل (رابط دائم واحد لكل عميل)
├── api/
│   ├── chat.js                 ← الوسيط الآمن مع Anthropic + استخراج المسودات تلقائيًا
│   ├── drafts.js                ← إدارة دورة حياة المسودة (إنشاء/مراجعة/اعتماد/إرسال)
│   ├── auth.js                  ← تسجيل الدخول وإصدار جلسة موقّعة
│   ├── _auth.js                 ← تشفير كلمة المرور + التحقق من الجلسات + حماية Brute-Force
│   ├── _db.js                   ← اتصال بقاعدة بيانات Upstash Redis
│   ├── client-portal.js         ← بيانات أرشيف عميل معيّن
│   ├── client-portal-link.js    ← جلب رابط أرشيف عميل (للوحة التحكم)
│   ├── _mailchimp.js            ← وحدة OAuth + إنشاء وإرسال حملات Mailchimp
│   ├── mailchimp-connect.js     ← توليد رابط تفويض Mailchimp لعميل معيّن
│   └── mailchimp-callback.js    ← استقبال موافقة العميل وربط حسابه
├── scripts/
│   └── hash-password.js  ← سكربت تشغّله مرة واحدة على جهازك لتوليد كلمة مرور مشفّرة
├── vercel.json
└── README.md
```

## خطوات النشر

1. **رفع المجلد على GitHub** ثم **استيراده على Vercel** (Add New Project → Import)

2. **إضافة مفتاح Anthropic API**
   - Settings → Environment Variables → `ANTHROPIC_API_KEY`

3. **إضافة قاعدة بيانات Upstash**
   - أنشئ حسابًا مجانيًا على upstash.com → أنشئ قاعدة بيانات Redis جديدة
   - انسخ **REST URL** و **REST Token** إلى متغيرات البيئة:
     - `UPSTASH_REDIS_REST_URL`
     - `UPSTASH_REDIS_REST_TOKEN`

4. **إعداد تسجيل الدخول الحقيقي للوحة التحكم (جديد)**
   - على جهازك (يحتاج Node.js مثبّتًا)، شغّل:
     ```
     node scripts/hash-password.js "كلمة_المرور_التي_تريدها"
     ```
   - انسخ الناتج الطويل (شكل: `salt:hash`) وأضفه بمتغيرات البيئة:
     - `ADMIN_PASSWORD_HASH` = الناتج من السكربت
     - `ADMIN_EMAIL` = إيميلك الذي ستدخل فيه للوحة
     - `SESSION_SECRET` = أي نص عشوائي طويل من اختيارك (يُستخدم لتوقيع الجلسات بأمان — لا تشاركه مع أحد)
   - **لا تضع كلمة المرور الصريحة بأي مكان** — فقط الناتج المشفّر من السكربت

5. **إعادة النشر** بعد إضافة كل المتغيرات (Deployments → Redeploy)

6. **ربط الدومين** — Settings → Domains → أضف `inboxloops.com` وأضف سجلات DNS المعطاة بلوحة تحكم الدومين لديك

## كيف يعمل تسجيل الدخول الآن (بعد التحسين الأمني)

- كلمة المرور **لا تُخزَّن أبدًا كنص صريح** — فقط بصيغة مشفّرة (scrypt) بمتغيرات البيئة
- عند الدخول، الخادم يتحقق من الإيميل وكلمة المرور، ويصدر **رمز جلسة موقّع (Session Token)** صالح لمدة 7 أيام
- كل طلب لاحق (عرض/اعتماد المسودات) يرسل هذا الرمز بدل كلمة المرور نفسها
- حماية من محاولات الدخول العشوائية: بعد 5 محاولات فاشلة من نفس الجهة، حظر مؤقت 15 دقيقة

## كيف تعمل الحلقة الكاملة

1. العميل يرسل محتوى الأسبوع بالشات → مسودة تُحفظ تلقائيًا (بانتظار مراجعتك)
2. تدخل `yourdomain.com/admin.html` بإيميلك وكلمة مرورك → تراجع/تعدّل → "اعتماد وإرسال للعميل"
3. ترسل يدويًا رابط المراجعة للعميل: `yourdomain.com/review.html?id=DRAFT_ID&token=MAGIC_TOKEN`
4. العميل يوافق أو يطلب تعديل
5. ترجع للوحة وتضغط "تأكيد الإرسال الفعلي"

## ربط حسابات Mailchimp الفعلي (Connected Accounts — جديد)

الآن الإرسال الفعلي يمكن أن يتم تلقائيًا داخل حساب Mailchimp الخاص بكل عميل، عبر OAuth 2.0 الرسمي.

### إعداد لمرة واحدة (بحساب Mailchimp الخاص بالوكالة)
1. سجّل دخول على mailchimp.com، واذهب لصفحة **Register an App**: `https://[your-account].admin.mailchimp.com/account/oauth2/`
2. أنشئ تطبيقًا جديدًا، وضع **Redirect URI** بالضبط كالتالي:
   `https://inboxloops.com/api/mailchimp-callback`
3. انسخ **Client ID** و **Client Secret** الناتجين، وأضفهما بمتغيرات البيئة على Vercel:
   - `MAILCHIMP_CLIENT_ID`
   - `MAILCHIMP_CLIENT_SECRET`
4. أعد النشر (Redeploy)

### كيف يعمل الربط لكل عميل جديد
1. من لوحة التحكم، اضغط **"🔗 ربط Mailchimp للعميل"** بجانب أي مسودة له
2. يُنسخ رابط تفويض Mailchimp تلقائيًا — أرسله للعميل (بريد/واتساب)
3. العميل يفتح الرابط، **يسجّل دخول بحسابه هو على Mailchimp**، ويوافق على منح الوكالة صلاحية
4. تلقائيًا، حسابه يُربط بسجله عندنا (يشمل أول قائمة بريدية بحسابه كافتراضي)
5. من هذه اللحظة، أي نشرة يوافق عليها هذا العميل تُرسل **تلقائيًا وفعليًا** لقائمته البريدية عند ضغطك زر "تأكيد الإرسال الفعلي"

### ⚠️ تبسيطات مقصودة بالربط الفعلي
- **يُستخدم أول قائمة بريدية بحساب العميل تلقائيًا** — لو عنده أكثر من قائمة، يحتاج اختيار القائمة المطلوبة يُضاف لاحقًا كخطوة إضافية بالربط
- **بدون شاشة اختيار مسبقة للمحتوى داخل Mailchimp قبل الإرسال** — الحملة تُنشأ وتُرسل مباشرة بضغطة الزر، فتأكد من اعتماد كل من الوكالة والعميل قبل الضغط على "تأكيد الإرسال الفعلي"
- **العميل يقدر يلغي الصلاحية بأي وقت** من إعدادات حسابه على Mailchimp (Settings → Connected Sites/Apps)، وإذا ألغاها، سيفشل الإرسال التالي وتحتاج إعادة الربط
- **عميل بدون ربط Mailchimp** يبقى يعمل بالمسار اليدوي القديم تلقائيًا (تحديث الحالة فقط دون إرسال فعلي)

## أمان رابط المراجعة + أرشيف العميل (جديد)

- **رابط المراجعة لكل نشرة** الآن رمز عشوائي طويل (32 بايت) + صلاحية 14 يوم، ويُولَّد رمز جديد تمامًا في كل مرة تعتمد فيها الوكالة مسودة (بدل رمز ثابت من البداية)
- كل إجراء من العميل (موافقة/طلب تعديل) **يتحقق فعليًا من الرمز وصلاحيته على السيرفر**، وليس فقط عند فتح الصفحة — كانت هذه فجوة أمنية بالنسخة السابقة تم إغلاقها
- لو انتهت صلاحية الرابط قبل رد العميل، اضغط زر **"🔗 توليد رابط جديد"** بجانب المسودة بلوحة التحكم
- **أرشيف دائم لكل عميل**: زر **"📋 نسخ رابط أرشيف العميل"** بلوحة التحكم يعطيك رابطًا ثابتًا (`portal.html?email=...&token=...`) ترسله للعميل **مرة واحدة فقط** — يعرض له كل نشراته السابقة والحالية بحالاتها، ويفتح منه أي نشرة قديمة للقراءة

## ⚠️ تبسيطات مقصودة بهذه النسخة (لازم تعرفها)

- **حساب واحد فقط مدعوم حاليًا** (لك أنت) — دعم عدة مستخدمين بصلاحيات مختلفة يحتاج توسعة لاحقة بسيطة
- **تصنيف تعديل العميل (بسيط/جوهري) غير تلقائي** — كل تعديل يرجع لك يدويًا بحالة "⚠️ العميل طلب تعديل جوهري"
- **رابط مراجعة العميل يُرسَل يدويًا منك** — لا بريد تلقائي بعد (يحتاج Resend/SendGrid لاحقًا)
- **الإرسال الفعلي للنشرة يبقى يدويًا** — يحتاج آلية Connected Accounts الموضحة بالمواصفات التقنية
- **حماية Brute-Force داخل الذاكرة (In-Memory)** — أفضل جهد فقط، مثل حد استخدام الشات، وقد لا تكون دقيقة 100% عبر كل نسخ السيرفرلس

## الخطوة التالية بعد النشر
اختبر الحلقة كاملة: سجّل دخول للوحة بإيميلك وكلمة مرورك → أرسل محتوى بالشات → تأكد وصول المسودة → اعتمدها → افتح رابط المراجعة → وافق أو اطلب تعديل → تأكد رجوعها بالحالة الصحيحة.

## تحديثات إضافية: مراحل المراجعة + جمع المحتوى + ضمان الوصول

### 1. مراجعة كاملة مع تمييز الشك (بدل فلترة Potions)
المسودة تُعرض لك **كاملة دائمًا** (تبويب "معاينة كيف تبدو فعليًا")، لكن أي جزء غير متأكد منه
المساعد (رقم غير مؤكد، ادعاء يحتاج تحققًا) يظهر مظللًا بالأصفر مع توضيح السبب عند تمرير الفأرة.
هذا التظليل يُزال تلقائيًا من النص النهائي فور اعتمادك — العميل لا يرى أي علامات.

### 2. سحب محتوى تلقائي من رابط العميل
لو أرسل العميل رابط موقعه/مدونته/منشور بدل كتابة محتوى مباشر، `chat.js` يجلب نص الصفحة
تلقائيًا (حد أقصى 8 ثوانٍ و4000 حرف) ويستخدمه المساعد كمصدر لصياغة النشرة، بدون أي إعداد إضافي.

**تبسيط مقصود:** الجلب نص خام مبسّط (إزالة وسوم HTML فقط) — لا يفهم بنية الصفحة أو يفرّق بين
المقالة الرئيسية والقوائم الجانبية، فقد يلتقط نصًا زائدًا من صفحات معقدة.

### 3. فحص ضمان الوصول (SPF/DMARC) إلزامي قبل أول إرسال تلقائي
عند ربط حساب Mailchimp لأي عميل، يتم فحص سجلات SPF وDMARC لنطاق إيميله تلقائيًا. لو لم تجتز،
**زر "تأكيد الإرسال الفعلي" سيرفض الإرسال** ويعرض لك تحذيرًا صريحًا، مع خيار تجاوزه إن أصررت.
زر "🛡️ فحص ضمان الوصول" بلوحة التحكم يعيد الفحص يدويًا بأي وقت (مفيد بعد ما يصلح العميل إعداداته).

**ملاحظة:** DKIM لا يُفحص آليًا (يعتمد على "selector" خاص بكل حساب Mailchimp) — يحتاج تحقق يدوي
من تبويب Domain Authentication داخل حساب Mailchimp للعميل.

## تحسينات الأداء المُطبَّقة

1. **إزالة استدعاء شبكي داخلي زائد**: `chat.js` كان يحفظ المسودة عبر طلب HTTP كامل لنفسه
   (`fetch /api/drafts`)، وهو ما يضيف دورة شبكة إضافية كاملة (DNS + TLS + احتمال Cold Start
   لدالة ثانية) بكل رسالة فيها مسودة. الآن يستدعي دالة `createDraft()` مباشرة من نفس العملية
   — تم التأكد باختبار فعلي أن لا يوجد أي طلب شبكي غير ضروري بعد الإصلاح.
2. **تحميل الخطوط بدون حجب عرض الصفحة**: أُضيف `preconnect` لنطاق `fonts.gstatic.com` (كان
   مفقودًا بكل الصفحات)، وتحميل ملف الخطوط بطريقة غير حاجبة (`media="print"` مع تبديل تلقائي)
   حتى تظهر الصفحة فورًا بخط احتياطي بدل انتظار تحميل الخط الكامل.

## 🔴 إصلاح حرج: فقدان بيانات عند التزامن (Race Condition)

اختبار حمل محلي كشف أن إرسال عدة عملاء لمحتوى بنفس اللحظة تقريبًا كان **يفقد فعليًا حتى
9 من كل 10 مسودة** بصمت، بسبب طريقة الفهرسة القديمة (قراءة قائمة → تعديل بالذاكرة → كتابة
كاملة) التي تتجاهل تعديلات الطلبات المتزامنة الأخرى. تم استبدالها بعملية **Redis Set ذرّية
(SADD/SMEMBERS)** تُنفَّذ بالكامل على مستوى قاعدة البيانات نفسها، وتأكد الإصلاح باختبار محلي
لعشر عمليات إنشاء متزامنة (نتيجة: 10/10 بدون فقدان، بعد أن كانت 1/10 قبل الإصلاح).

## إضافات جديدة أخرى بهذه الجولة

1. **تنبيهات تيليجرام فورية** — أضف `TELEGRAM_BOT_TOKEN` و `TELEGRAM_CHAT_ID` بمتغيرات البيئة
   لتصلك تنبيهات فورية عند: مسودة جديدة، عميل محتمل جديد، تصعيد عاجل، أو طلب تعديل من عميل.
   بدون هذين المتغيرين، النظام يعمل طبيعيًا لكن بدون تنبيهات فورية (تراجع اللوحة يدويًا فقط).
2. **سجل عملاء محتملين فعلي** — كان يُذكر بالمحادثة فقط، الآن يُخزَّن فعليًا ويظهر بقسم جديد
   بلوحة التحكم "عملاء محتملون جدد".
3. **صفحة 404 مخصصة** (`public/404.html`) — Vercel يستخدمها تلقائيًا لأي رابط غير موجود.
4. **سياسة الخصوصية وشروط الاستخدام** (`public/privacy.html`, `public/terms.html`) — مرتبطة
   بأسفل الصفحة الرئيسية. **ملاحظة: نصوص عامة أولية، يُنصح بمراجعتها قانونيًا قبل الاعتماد
   الكامل عليها، خصوصًا مع نمو عدد العملاء.**

## ما زال ناقصًا (صريح، لم يُبنَ بهذه الجولة)

- **نسخ احتياطي تلقائي لقاعدة البيانات**: Upstash تقدّم نسخًا احتياطيًا تلقائيًا على الخطط
  المدفوعة فقط. بالخطة المجانية، النسخ الاحتياطي مسؤوليتك — يُنصح لاحقًا ببناء نقطة نهاية
  تصدير دوري (Export) لكل البيانات كملف JSON تحفظه بمكان آخر.
- **اختبار حمل حقيقي على السحابة**: الاختبار المحلي أثبت أن منطق الكود سليم بعد الإصلاح، لكن
  لم يُختبر أداء Upstash الفعلي تحت ضغط حقيقي (حدود الخطة المجانية: عدد أوامر محدود شهريًا).
